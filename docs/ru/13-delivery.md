# 13. Webhook и long polling

Telegram поддерживает два способа доставки апдейтов боту, и оба реализованы во фреймворке —
переключаться между ними не нужно, они используют один и тот же пайплайн обработки.

## 13.1 В чём разница

| | Long polling | Webhook |
|---|---|---|
| Как получает апдейты | Бот сам постоянно спрашивает Telegram: «есть новые апдейты?» | Telegram сам присылает POST-запрос на ваш URL |
| Нужен публичный HTTPS | Нет | Да |
| Подходит для | Локальной разработки | Продакшена |
| Как запускается | `php artisan telegram:poll` — держит процесс открытым | Обычный HTTP-роут, отдельного процесса не требует |

## 13.2 Long polling для разработки

```bash
php artisan telegram:poll default
```

Без аргумента команда предложит выбрать бота из списка интерактивно:

```bash
php artisan telegram:poll
```

Перед стартом команда сама проверяет, не установлен ли у бота вебхук (Telegram разрешает только
один способ доставки одновременно), и если он есть — предложит его снять, вручную вызывать
`telegram:delete-webhook` не нужно.

Полезные флаги:

| Флаг | Что делает |
|---|---|
| `--timeout=30` | Таймаут long-poll запроса к Telegram, в секундах |
| `-o`, `--show-outgoing` | Показывать в консоли ещё и исходящие вызовы API бота, не только входящие апдейты |
| `--only=message --only=callback_query` | Показывать/обрабатывать только перечисленные типы апдейтов |
| `--user=123456789` | Только апдейты от указанных Telegram user id |
| `--dry-run` | Показывать апдейты, но **не** передавать их в хендлеры бота — удобно для инспекции трафика без побочных эффектов |
| `-l`, `--log-traffic` | Писать сырые входящие/исходящие данные в `storage/logs/telegram-traffic.log` |

```bash
php artisan telegram:poll default --only=callback_query --user=123456789 --dry-run
```

Ошибки во время long polling не останавливают команду: сбой `getUpdates` уходит в экспоненциальный
backoff (5с, 10с, 20с… до 60с), а необработанное исключение внутри конкретного хендлера логируется
и не прерывает обработку следующих апдейтов.

Long polling держит процесс на переднем плане и не предназначен для продакшена за процесс-менеджером.

## 13.3 Webhook для продакшена

```bash
php artisan telegram:set-webhook default
php artisan telegram:delete-webhook default
```

Каждый бот получает свой маршрут вида `POST /telegram/webhook/{botName}`. Подлинность запроса
проверяется секретным токеном, который Telegram присылает в заголовке — он выводится
детерминированно из `APP_KEY` приложения и токена бота, поэтому подделать его без знания `APP_KEY`
нельзя. Отдельно хранить и синхронизировать секрет между окружениями не требуется — при смене
`APP_KEY` или токена бота секрет пересчитается автоматически, вебхук достаточно переустановить.

## 13.4 Что выбрать

Разрабатывайте локально через `telegram:poll` (не нужен туннель/HTTPS), а в продакшен
выкладывайте через webhook (`telegram:set-webhook`). Смешивать их для одного бота нельзя —
Telegram отключает одно при включении другого, поэтому команда `telegram:poll` и предупреждает
об этом заранее.
