# 16. Отладка и диагностика

## 16.1 Список всех маршрутов бота

```bash
php artisan telegram:routes shop
php artisan telegram:routes shop --type=commands
```

Показывает все зарегистрированные команды, callback-паттерны и текстовые триггеры конкретного
бота, а также отмечает, какие из них требуют авторизации (`RequiresPermission`). Без указания
бота — маршруты сразу всех зарегистрированных ботов.

Это самый быстрый способ проверить опечатку в паттерне или убедиться, что хендлер вообще
зарегистрирован, не читая код бота целиком.

## 16.2 Просмотр трафика без выполнения хендлеров

```bash
php artisan telegram:poll shop --dry-run
```

Показывает все входящие апдейты в реальном времени, но не передаёт их в хендлеры бота — удобно,
когда нужно понять, что именно приходит от Telegram (например, разобраться в структуре
`callback_data` от стороннего клиента), не рискуя случайно запустить диалог или изменить данные.

## 16.3 Логирование трафика в файл

```bash
php artisan telegram:poll shop -l
```

Пишет сырые входящие и исходящие данные в `storage/logs/telegram-traffic.log` — полезно, когда
баг не воспроизводится «на глаз» в консоли и нужно приложить лог к issue или посмотреть его позже.

## 16.4 Чек-лист «бот не отвечает»

1. Не запущены ли одновременно webhook и `telegram:poll` для одного бота — Telegram отдаёт апдейты
   только одним способом, второй будет молчать (см. [13.4](13-delivery.md#134-что-выбрать)).
2. Для webhook — доступен ли URL снаружи по HTTPS, отвечает ли он 200, не блокирует ли
   `VerifyWebhookSecretMiddleware` запрос из-за несовпавшего секрета (проверьте `APP_KEY` и токен
   бота — секрет выводится из них детерминированно).
3. Зарегистрирован ли вообще нужный хендлер — `php artisan telegram:routes {bot}`.
4. Есть ли активный диалог у этого пользователя — во время диалога апдейт уходит в текущий шаг
   диалога, а не в обычные роутеры (см. [10.3](10-dialogs.md#103-регистрация-диалога)); если шаг
   ничего не отвечает, ищите баг в `Step::handle()`.
5. Не отфильтровал ли апдейт `middleware()` бота, тихо не вызвав `$next()` (см.
   [12. Middleware](12-middleware.md)).
6. Не отклонил ли доступ `RequiresPermission::authorize()`, вернув `false` без
   `HasUnauthorizedMessage` — снаружи это выглядит как полное молчание бота.
