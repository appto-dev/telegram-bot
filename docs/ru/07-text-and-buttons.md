# 7. Обычный текст и триггеры

## 7.1 Точное совпадение текста

```php
$this->onText('hello', HelloHandler::class);
```

`onText()` срабатывает только на **дословное** совпадение текста сообщения с указанной строкой —
без учёта регистра и без учёта пробелов по краям (`" Hello "` совпадёт с `'hello'`), но это не
поиск по подстроке и не регулярное выражение: если пользователь допишет к тексту что-то ещё
(например, `hello!`), хендлер не вызовется. Если в сообщении нет текста, но есть подпись к медиа
(фото, документ) — сравнение идёт с ней.

## 7.2 Когда это подходит

`onText()` предназначен прежде всего для reply-кнопок (кнопки под полем ввода) — их текст известен
заранее и всегда совпадает дословно, потому что пользователь именно нажимает кнопку, а не печатает
текст сам. Использовать `onText()` для разбора произвольных фраз пользователя не стоит — для
свободного ввода лучше подходит команда с аргументом или шаг диалога (см. [10. Диалоги](10-dialogs.md)).

## 7.3 Пример с reply-клавиатурой

Обычно текст триггера хранят рядом с разметкой самой клавиатуры, чтобы не рассинхронизировать
текст на кнопке и текст в `onText()`:

```php
class GlobalReplyMarkup
{
    public const string CABINET_LABEL_TRIGGER = '⚙️ Мой кабинет';

    public static function make(): ReplyKeyboardMarkup
    {
        return ReplyKeyboardMarkup::from([
            'keyboard' => [[
                KeyboardButton::from(['text' => self::CABINET_LABEL_TRIGGER]),
            ]],
            'resize_keyboard' => true,
        ]);
    }
}
```

```php
$this->onText(GlobalReplyMarkup::CABINET_LABEL_TRIGGER, CabinetCommand::class);
```

Так текст кнопки существует в проекте в одном месте — константе — и используется и при построении
клавиатуры, и при регистрации триггера.
