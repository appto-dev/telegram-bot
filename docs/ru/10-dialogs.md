# 10. Диалоги

## 10.1 Когда нужен диалог

Диалог нужен, когда ответ пользователя должен «запомниться» между сообщениями — то есть сценарий
не укладывается в одно сообщение. Классический пример — регистрация: сначала спросить имя,
дождаться ответа, затем спросить e-mail, дождаться ответа, и только потом всё сохранить.

Если весь ввод умещается в одну команду с аргументами или в нажатие одной кнопки — диалог избыточен,
достаточно обычной команды или callback-хендлера (см. [3.4](03-development-philosophy.md#34-что-использовать-команда-кнопка-или-диалог)).

## 10.2 Из чего состоит диалог

Диалог — класс-наследник `Dialog`, который перечисляет свои шаги по порядку:

```php
final class RegistrationDialog extends Dialog
{
    public function steps(): array
    {
        return [
            'name' => AskName::class,
            'gender' => AskGender::class,
            'email' => AskEmail::class,
        ];
    }

    public function onComplete(UpdateContext $context, array $answers): void
    {
        // $answers — данные всех шагов, ключ = имя шага
        $context->reply('Регистрация завершена 🎉');
    }

    public function onCancel(UpdateContext $context): void
    {
        $context->reply('Регистрация отменена');
    }
}
```

Каждый шаг — отдельный класс, реализующий `Step`, с двумя методами: `enter()` — что показать
пользователю при входе на шаг, и `handle()` — что делать с его ответом:

```php
class AskName implements Step
{
    public function enter(DialogContext $context): void
    {
        $context->update->reply('Как вас зовут?');
    }

    public function handle(DialogContext $context): StepResult
    {
        $text = $context->update->message()?->text;

        if (empty($text)) {
            $context->update->reply('Имя обязательно, попробуйте ещё раз');

            return StepResult::repeat();
        }

        return StepResult::next($text);
    }
}
```

`DialogContext` внутри шага даёт доступ к обычному `UpdateContext` (`$context->update`), к ответам
предыдущих шагов (`$context->answer('name')`) и к имени текущего шага.

## 10.3 Регистрация диалога

Диалог регистрируется точно так же, как обычный хендлер — как команда, callback или текстовый
триггер:

```php
$this->onCommand('start', RegistrationDialog::class);
// или
$this->onCallback('dialog:login', LoginDialog::class);
```

Отдельного «реестра диалогов» не существует: диалог начинается в тот момент, когда фреймворк
доходит до него как до обычного хендлера команды/кнопки/текста.

## 10.4 Что возвращает шаг

Метод `handle()` шага возвращает `StepResult`, который решает, что происходит дальше:

| Фабрика | Что делает |
|---|---|
| `StepResult::next($data)` | Сохранить `$data` и перейти к следующему шагу по порядку из `steps()` |
| `StepResult::back()` | Вернуться к предыдущему шагу |
| `StepResult::goto('stepName', $data)` | Перейти к произвольному шагу по имени (не обязательно соседнему) |
| `StepResult::repeat()` | Остаться на этом же шаге (например, при невалидном вводе) |
| `StepResult::complete($data)` | Завершить диалог — вызовется `onComplete()` со всеми ответами |
| `StepResult::cancel()` | Отменить диалог — вызовется `onCancel()` |
| `StepResult::restart()` | Начать диалог заново с первого шага |
| `StepResult::switchTo(OtherDialog::class)` | Переключиться на другой диалог целиком |

`next()` на последнем шаге и `back()` на первом — логическая ошибка (нет следующего/предыдущего
шага), поэтому такой шаг должен возвращать `complete()`/`cancel()` соответственно, а не `next()`/`back()`.

## 10.5 Данные на выходе

`onComplete()` получает массив `$answers`, где ключ — имя шага (как в `steps()`), а значение — то,
что вернул этот шаг через `next()`/`complete()`. Это единственное место, где стоит писать в базу
данных или выполнять финальную бизнес-логику — не раньше, чтобы не сохранять неполные данные, если
пользователь отменит диалог на середине.

## 10.6 Отмена диалога

Встроенная команда `/cancel` отменяет активный диалог:

```php
use Appto\TelegramBot\Dialog\CancelCommand;

$this->onCommand('cancel', CancelCommand::class);
```

Кроме того, **любая** команда, введённая посреди диалога, автоматически его отменяет (вызывается
`onCancel()`), а сама команда после этого обрабатывается как обычно — то есть пользователь не
«застревает» в диалоге, если передумал и написал `/start` заново.

## 10.7 Частые ошибки

- Забыть про `back()` на первом шаге / `next()` на последнем — приведёт к ошибке в рантайме.
- Писать в базу данных внутри `Step::handle()`, а не в `Dialog::onComplete()` — если пользователь
  отменит диалог, данные останутся частично сохранёнными.
- Не валидировать ввод в `handle()` перед `next()` — пустой/некорректный ответ должен приводить к
  `repeat()` с понятным сообщением, а не проходить дальше как есть.
