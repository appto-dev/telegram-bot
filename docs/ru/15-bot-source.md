# 15. Откуда бот берёт список ботов

## 15.1 Простой способ — конфиг (по умолчанию)

```env
TELEGRAM_BOT_REPOSITORY=config
```

Список ботов — статический массив в `config/telegram-bot.php` (`bots`). Подходит для
подавляющего большинства проектов: боты известны заранее, добавляются разработчиком через код и
деплой.

## 15.2 Гибкий способ — база данных

```env
TELEGRAM_BOT_REPOSITORY=database
```

Список ботов хранится в таблице БД (токен — в зашифрованном виде). Имеет смысл, когда боты
создаются динамически — например, если ваше приложение само является SaaS-платформой, и каждый
клиент подключает своего бота через интерфейс, без участия разработчика и без деплоя.

Перед переключением опубликуйте и накатите миграцию:

```bash
php artisan vendor:publish --tag=telegram-bot-migrations
php artisan migrate
```

## 15.3 Как переключиться

Изменения ограничиваются одной переменной окружения `TELEGRAM_BOT_REPOSITORY` — код ботов
(классы-наследники `Bot`, хендлеры, диалоги) от источника списка никак не зависит и переписывать
его не нужно.

## 15.4 Перенос ботов из конфига в базу

Если боты уже описаны в `config/telegram-bot.php` (`bots`) и вы переключаетесь на `database`,
не нужно переносить их вручную — есть команда:

```bash
php artisan telegram:migrate-bots-to-database [--force] [--dry-run]
```

Она читает `config('telegram-bot.bots')` и создаёт/обновляет соответствующие строки в
`telegram_bots` (по `name` = ключу бота в конфиге). Без флагов существующие в БД боты не
трогает — пропускает с пометкой `skipped`; `--force` перезаписывает их данными из конфига;
`--dry-run` показывает, что произойдёт, без записи в БД. После переноса переключите
`TELEGRAM_BOT_REPOSITORY=database` (см. 15.3) — старую запись в `bots` конфига можно оставить,
источник данных на неё больше не смотрит. Команда не заполняет кастомную колонку ключа вебхука
(см. 15.5) — после переноса забэкфильте её вручную.

## 15.5 Свой ключ для вебхука (только database)

По умолчанию маршрут вебхука — `/telegram/webhook/{name}`, то есть тот же человекочитаемый
алиас, что используется в `telegram:poll`, `telegram:set-webhook` и т.д. Это предсказуемо/угадываемо,
что не всегда приемлемо для публичного продакшен-URL.

При `repository = database` можно направить маршрут вебхука на другую колонку:

```php
// config/telegram-bot.php
'database' => [
    'webhook_key_column' => 'uuid',
],
```

Пакет эту колонку не создаёт и не мигрирует — добавьте её сами своей миграцией, расширяющей
`telegram_bots`, и убедитесь, что она уникальна и заполнена у каждого активного бота:

```php
Schema::table('telegram_bots', function (Blueprint $table) {
    $table->uuid('uuid')->nullable()->unique()->after('name');
});
```

Как только `webhook_key_column` указывает на неё, `telegram:set-webhook` строит URL по значению
этой колонки, а не `name`, и входящие запросы вебхука сверяются с ней же. CLI-команды не
затрагиваются — `telegram:poll`, `telegram:set-webhook`, `telegram:delete-webhook` и
`telegram:routes` по-прежнему принимают `name` бота, меняется только маршрут/URL вебхука.

Если у активного бота значение в настроенной колонке пустое, фреймворк бросает исключение вместо
тихого отката на `name` — лучше явно узнать о пропущенном значении, чем рисковать маршрутизацией
вебхука не на того бота.
